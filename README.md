# エオルゼア蒐集録 — 統合検索UI版

この版では、ロードストーンIDを**一度だけ**入力して、マウント、ミニオン、アチーブメントの所持状況をまとめて確認できます。FFXIV Collectへのキャラクター登録やログインは必要ありません。

検索開始後は、負荷の軽い**マウント／ミニオンを先に表示**し、アチーブメントは背景で取得を続けます。画面の切替タブは結果を閲覧するためだけのものであり、再検索は不要です。

| 結果タブ | 所持判定の取得方法 | 画面上の挙動 |
|---|---|---|
| マウント | 公開ロードストーンのコレクションアイコンをゲームデータのアイコンと視覚的に照合 | 先に表示 |
| ミニオン | 公開ロードストーンのコレクションアイコンをゲームデータのアイコンと視覚的に照合 | 先に表示 |
| アチーブメント | 公開ロードストーンの一覧から `/achievement/detail/{ID}/` の数値IDを全ページ取得 | 背景で取得し、完了後にタブで表示 |

> マウント／ミニオンは名前のスクレイピングに依存せず、40pxアイコンの視覚的シグネチャを照合します。アチーブメントはロードストーンが表示する数値IDを用いるため、画面の言語設定に左右されません。

## 構成

| パス | 内容 |
|---|---|
| `public/index.html` | 単一入力・段階表示の統合UI。マウント／ミニオンを先に描画し、アチーブメント取得状況を表示する。 |
| `worker.js` | `/api/lodestone-collections`、`/api/lodestone-achievements`、および安全な画像プロキシ `/api/lodestone-icon` を提供するStatic Assets Worker。 |
| `wrangler.toml` | Cloudflare Worker設定。公開アセットは `public/` のみ。 |
| `tests/verify-live-registration-free.mjs` | ライブの公開ロードストーンからマウント／ミニオンを抽出する回帰テスト。 |
| `tests/verify-icon-pixel-match.py` | マウント／ミニオンの視覚シグネチャ照合を検証するテスト。 |
| `tests/verify-lodestone-achievements.mjs` | 公開アチーブメント一覧のページ数と達成ID総数を検証するテスト。 |
| `tests/verify-achievement-chunks.mjs` | 10ページ単位のアチーブメント取得フローを検証するテスト。 |
| `RESTORATION_REVIEW.md` | 元のブランドUIを基準にしたファビコン、SVGロゴ、入手率リングの復元確認記録。 |

## デプロイ

CloudflareのWorker名が `eorzean-collection` の場合、リポジトリ直下の既存ファイルをこのプロジェクト一式で置き換えます。`worker.js`、`wrangler.toml`、`public/` を同じコミットで反映してください。

```bash
# 例: Git Bash
cp -r eorzean-collection-update/. eorzean-collection/
cd eorzean-collection
git add -A
git commit -m "fix: restore original branding and acquisition rate rings"
git push
```

## 検証

検証用の公開キャラクターIDは `25961161` です。ゲーム側の取得状況や一覧ページが更新された場合は、期待値を更新してください。

```bash
# 1. マウント／ミニオンの登録不要抽出
node tests/verify-live-registration-free.mjs 25961161

# 2. マウント／ミニオンのアイコン照合
python3 tests/verify-icon-pixel-match.py 25961161

# 3. アチーブメントの全ページID抽出
EXPECTED_ACHIEVEMENTS=2317 EXPECTED_ACHIEVEMENT_PAGES=47 \
  node tests/verify-lodestone-achievements.mjs 25961161

# 4. アチーブメントの10ページ単位の統合フロー
EXPECTED_ACHIEVEMENTS=2317 node tests/verify-achievement-chunks.mjs 25961161

# 5. マーケット・入手性・課金要素の分類ルール
node tests/verify-collection-classification.mjs
```

検証時点で、公開ロードストーンはマウント227件、ミニオン431件、アチーブメント2,317件を返しました。統合UIでは、初回のアイコン照合完了後にマウント／ミニオンを表示し、アチーブメントは取得完了まで「取得中」と明示します。アチーブメントだけが非公開または取得失敗した場合も、マウント／ミニオン結果はそのまま利用できます。

## 運用上の注意

アチーブメントは一括で全ページを取得せず、Workerが一回につき最大10ページを返し、ブラウザが完了まで統合します。結果はWorker側で1時間キャッシュされます。画像プロキシは `lds-img.finalfantasyxiv.com/itemicon/` のHTTPS PNGだけを許可し、任意URLの取得を拒否します。ロードストーンのコレクション結果は15分、アイコン画像は7日間キャッシュします。

## 復元したブランドUI

機能追加前に存在した次のUI要素を復元しています。登録不要の照合、アチーブメントの段階取得、追加フィルターとの両立を保っています。

| 復元要素 | 実装 |
|---|---|
| ファビコン | 元サイトと同じ水晶モチーフのインラインSVGを `rel="icon"` として設定。 |
| トップロゴ | 水晶マークのSVG、サイト名、`EORZEAN COLLECTION` のサブタイトルを含むブランドヘッダー。 |
| 入手率リング | 検索後にマウント、ミニオン、アチーブメントの所持率と件数を3つのアニメーションSVGリングで表示。アチーブメント取得中は進行状態を明示。 |
| 結果ボード | 元の水晶紫・獲得金の配色、上端のグラデーションライン、キャラクターカードの構造を復元。 |

## マウント・ミニオンの追加フィルター

マウント／ミニオンの結果画面では、入手先・所持状態・名前に加えて次の条件で絞り込みと並び替えができます。各カードにも同じ判定タグを表示します。

| 条件 | 判定 | 絞り込み／並び替え |
|---|---|---|
| マーケットボード | FFXIV Collectの `tradeable` フィールド | `MB購入可`／`MB購入不可`、および購入可を先頭へ並び替え |
| 現在入手可能性 | マーケットボード取引可、恒常コンテンツ、オンラインストア／コレクターズエディションを `通常入手可` とする。イベント、期間キャンペーン、PvPシリーズ、レガシー等のみのものは `期間限定・要確認` とする。 | `通常入手可`／`期間限定・要確認`、および通常入手可を先頭へ並び替え |
| 課金要素 | `Premium` のうちオンラインストア、コレクターズエディション、ゲームタイムカード由来のソース | `課金要素あり`／`課金要素なし`、および課金要素ありを先頭へ並び替え |

> データ提供元はイベントの開催中・終了日を直接返さないため、期間依存の入手手段を「現在入手不可」と断定しません。誤判定を避けるため、これらは **期間限定・要確認** と表示します。マーケットボードで取引できるものは、イベント終了後でも取引による入手経路があるため **通常入手可** と扱います。Twitch等の無償キャンペーンは、課金要素ではなく `キャンペーン系` とカードに表示します。

## レスポンシブ対応

統合検索UIは、画面幅に応じて検索・結果表示を切り替えます。

| 画面幅 | 主なレイアウト |
|---|---|
| 1060px以上 | フィルターを横一列のグリッド、結果カードを最小260pxの自動段組みで表示する。 |
| 781px〜1059px | フィルターを自然に折り返し、結果カードを最小220pxの自動段組みで表示する。 |
| 561px〜780px | 統計を3列、結果カードを2列で表示する。 |
| 560px以下 | 入力欄と検索ボタンを縦並びにし、結果タブ・状態絞り込み・フィルターを全幅で縦に表示する。結果カードは1列になる。 |
| 360px以下 | 長い日本語ラベルの表示を保つため、見出し・タブ・統計ラベルをさらに縮小する。 |

スマートフォンでは入力欄を16px以上、主要ボタンを48px以上の高さとしているため、ブラウザの意図しない拡大を抑え、タップ操作をしやすくしています。
